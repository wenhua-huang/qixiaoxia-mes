# 系统管理：账号、编码与平台维护

本文面向工厂的**系统管理员**，介绍账号权限怎么开、单据编码怎么改、消息待办怎么看，以及字典、参数、日志、API Key 等平台工具的用途。

系统管理的功能分布在两个入口：

- 顶部一级菜单「**系统管理**」：用户、角色、菜单、部门、岗位、字典、参数、公告、日志、API Key（平台级功能）。
- 「**MES 管理 → 系统管理**」：编码规则、编码记录、附件管理、系统消息、待办事项（MES 业务级功能）。

> 这些功能只建议管理员使用，普通操作员无需接触。

---

## 一、账号与权限

系统的权限模型是：**用户 → 角色 → 菜单权限**。用户能看到什么菜单、能点什么按钮，由他绑定的角色决定。

### 1. 新建一个能用的账号（标准三步）

1. **建部门 / 岗位（如已有可跳过）**：在 **系统管理 → 部门管理** 维护组织架构；在 **系统管理 → 岗位管理** 维护岗位（如"班组长""仓管员"）。
2. **建用户**：在 **系统管理 → 用户管理** 点「新增」，填用户昵称、归属部门、登录名、初始密码、手机号，勾选**岗位**和**角色**，保存。
3. **配角色权限（如角色已配好可跳过）**：在 **系统管理 → 角色管理** 编辑角色，在「菜单权限」树里勾选该角色能用的菜单和按钮，保存。

> 用户除了归属部门、岗位、角色外，还可以维护**员工类型、工资类型、入职日期、技能**等信息（计件工资和派工会用）；外协厂商账号需要额外**关联厂商**，且只能看到本厂外协相关数据。

### 2. 角色管理的三个要点

- **菜单权限**：决定左侧显示哪些菜单、列表上有哪些按钮（新增 / 修改 / 删除 / 导出）。新员工"看不到菜单"基本都是这里没勾。
- **分配用户**：角色列表上的「分配用户」可以把用户批量挂到角色下，与在用户表单里选角色等效。
- **数据权限**：控制角色能看到哪个部门的数据（全部 / 本部门 / 仅本人等），一般用默认值即可。

### 3. 菜单管理

**系统管理 → 菜单管理** 维护的是系统菜单本身（名称、路径、排序、图标）。日常**不需要动**，只有新增功能模块或调整菜单结构时才用；改错了会导致菜单打不开，请谨慎。

### 4. 多工厂说明

系统支持多工厂，数据按工厂隔离：

- 每个用户账号**绑定一个工厂**，登录后只能看到、只能操作本厂的数据。
- 用户绑定的工厂在账号开通时设定；如果一个员工要在多个工厂干活，需要各厂分别开账号。
- 对接外部系统的 API Key 也是**绑定工厂**的（见第六节）。

## 二、自动编码

工单号、领料单号、采购单号等单据编号不是随手编的，而是按「**编码规则**」自动生成。规则在 **MES 管理 → 系统管理 → 编码规则** 维护。

### 1. 编码规则是什么

一条规则由若干「**分段**」按顺序拼接而成，分段有四种类型：

| 分段类型 | 含义 | 关键配置 |
|---------|------|---------|
| **固定字符** | 不变的前缀，如 WO、ISS、FB | 固定字符内容 |
| **当前日期** | 生成时的日期，如 20261017 | 日期格式（如 yyyyMMdd） |
| **流水号** | 递增的序号，如 001、002 | 分段长度、起始值、步长、是否循环 |
| **输入字符** | 生成时临时传入的内容 | 默认输入字符 |

例如"固定字符 FB + 日期 yyyyMMdd + 3 位流水号"，生成的报工编码就是 `FB20261017001`。

流水号的「**循环方式**」决定序号什么时候归零重排：按年 / 按月 / 按日（常用，当天从 001 开始）/ 按小时 / 按分钟 / 按传入字符。规则本身还可以设置**最大长度、是否补齐**（不足长度时用补齐字符在左或右侧补齐）、**启用 / 停用**。

### 2. 修改一个单据的编码格式

以"把报工编码前缀从 FB 改成 BG"为例：

1. 打开 **MES 管理 → 系统管理 → 编码规则**，在列表中找到报工编码对应的规则（列表中点选该行）。
2. 下方出现「分段配置」卡片，点固定字符那一行的「修改」，把固定字符改成 `BG`。
3. 点列表上的「**生成编码**」按钮试生成一个，确认格式符合预期。

> **改动即时生效**：之后新建的单据按新格式编号，**已生成的旧单据编号不会变**。规则没有删除按钮，不用了就把它「停用」。

### 3. 哪些单据用了自动编码

系统中主要的自动编号对象包括：销售订单、采购订单、生产工单与流转卡、排产任务、报工记录、生产领料单、生产退料单、外协单、各类检验单、异常单、物料编码（按原料 / 半成品 / 成品 / 辅料 / 包材分规则）、批次号、入库单、销售出库单与发货单、班组与排班计划、工艺路线、工装等。

### 4. 编码记录能干什么

**MES 管理 → 系统管理 → 编码记录** 记录每条规则"哪天、生成到第几号、最后一个编码是什么"。用途有两个：

- **查问题**：怀疑跳号、重号时，来这里核对某条规则当天的最后流水号。
- **重置流水**：删除某条记录后，该规则对应周期的流水号会**从起始值重新排**。这是危险操作，可能导致新编号与历史单据重复，除非确认要重排，否则不要删。

## 三、系统消息与待办事项

### 1. 系统消息

**MES 管理 → 系统管理 → 系统消息** 是消息的统一台账，分四种类型：**系统消息、审批通知、预警通知、公告**。管理员可以：

- 按标题、类型、已读 / 未读筛选查看全厂消息；
- 手工「新增」一条消息发给指定用户（填接收用户、标题、类型、内容）；
- 批量「标记已读」或删除过期消息。

### 2. 待办事项

**MES 管理 → 系统管理 → 待办事项** 是全厂待办的总览页。待办大部分是**业务自动产生**的，典型场景：

- **待检验**：来料检、过程检、完工检、退货检的检验单生成后，自动产生"待检验"待办；检验判定完成后，对应待办自动关闭。
- **质检拦截**：过程检判定不合格时，系统自动给受影响任务的负责人（或报工人）生成高优先级拦截待办，提醒先处理质量问题再继续生产。

管理员在待办列表可以按类型（审批 / 质检 / 点检 / 保养 / 维修等）、状态（待处理 / 处理中 / 已完成 / 已驳回）筛选，也可以手工新增待办、修改、点「处理」填写处理意见关闭待办。

> 待办只是提醒，真正的业务处理（检验判定、审批）还是要到对应业务页面完成。

## 四、附件管理

**MES 管理 → 系统管理 → 附件管理** 是全厂附件的统一登记表：各业务单据上传的文件（如异常单的现场照片、单据上的图片和文档）都会在这里留下记录，包含原始文件名、文件类型、大小、所属单据类型、备注。

管理员的典型用法：

1. 按**原始文件名**或**单据类型**搜索，定位某个单据的附件；
2. 需要清理空间或删除误传文件时，勾选后删除；
3. 也可以在列表上直接「新增」补登一条附件记录、「修改」备注信息。

## 五、平台工具速览（顶部「系统管理」下）

| 功能 | 什么时候用 |
|------|-----------|
| **字典管理** | 维护下拉选项（如员工类型、工资类型、技能等级），新增选项先加字典再到页面使用 |
| **参数设置** | 维护系统级参数（如是否开启验证码），一般保持默认 |
| **通知公告** | 发布全厂公告 / 通知，发布后用户可在页面顶部的铃铛图标里查看 |
| **日志管理** | 查操作日志（谁在什么时候改了什么）和登录日志（谁在什么时候从哪登录），排查问题、追责用 |

## 六、API Key 管理（对接外部系统）

CRM 等外部系统要往 MES 自动推数据（如推销售订单）时，不使用账号密码，而是使用管理员签发的 **API Key**。

在 **系统管理 → API Key 管理** 点「生成凭证」：

1. 填**凭证名称**（如"CRM 生产环境"，方便日后识别）；
2. 选择**绑定工厂**——外部系统通过这个 Key 推入的数据只会进入该工厂；
3. 选填**过期时间**（不填则永不过期）；
4. 确定后页面会显示一次**明文 Key，仅显示这一次**，请立即复制并妥善转交给对接方。

后续管理：不再使用的凭证点「停用」（可恢复）或「吊销」（删除）。Key 泄露时应立即停用并重新生成。

> 对接方如何使用 API Key 调接口，请直接转交这篇文档：**[销售订单 API 对接指南](crm-order-api.md)**。

## 七、常见问题

**问：新员工登录后看不到任何菜单，或提示"无权限"？**
答：他的角色没配菜单权限。到 **系统管理 → 角色管理** 编辑该用户的角色，在「菜单权限」树里勾上对应菜单和按钮；或者检查 **用户管理** 里是否给他勾了角色。改完让用户重新登录。

**问：单据编码想改成自己习惯的格式，怎么改？**
答：到 **MES 管理 → 系统管理 → 编码规则**，找到对应规则，点选后在下方「分段配置」里修改前缀、日期格式或流水位数，改完用「生成编码」按钮试生成验证。旧单据编号不受影响。

**问：编码能重排吗？某天的流水号想从 1 重新开始。**
答：在 **编码记录** 里删除该规则当天的记录即可重排，但这会让新编号可能与历史单据重复，操作前务必确认，建议只停用旧规则、新建新规则来代替。

**问：某类单据突然不能自动编号了？**
答：先到 **编码规则** 检查对应规则是否被「停用」、分段是否完整（规则至少要配好分段才能生成），再用「生成编码」测试。规则正常但仍报错，联系实施方核对。

**问：用户离职 / 换岗怎么办？**
答：离职在 **用户管理** 把该用户状态改为停用即可（不要直接删，历史单据上的经手人还要显示）；换岗在用户表单里改**角色**和**岗位**。

**问：忘记了某员工的密码，或员工自己忘了密码？**
答：管理员在 **系统管理 → 用户管理** 对该用户使用"重置密码"功能设置新密码即可。

**问：质检员说没看到"待检验"的提醒？**
答：待办在检验单生成时自动产生，到 **MES 管理 → 系统管理 → 待办事项** 按类型"质检"筛选确认待办是否存在、状态是否为待处理；检验判定后待办会自动关闭，属正常现象。
