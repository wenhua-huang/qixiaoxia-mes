## 一、需求背景与目标

采购单（PO）完成后，需要一份**正式、可对外发给供应商**的文档，让供应商清楚「要什么、要多少、什么时候要、送到哪、什么条件」。这不是内部报表，而是**对外商务单据**（采购订单 / 采购合同）。

**核心诉求**（按优先级）：

1. **版式专业** —— 供应商看到的是「一张正式采购单」，而非系统导出的数据表
2. **信息完整** —— 物料、数量、交期、收货地址、联系人、付款条件不缺
3. **格式可用** —— PDF（正式、防篡改、版式固定、可邮件附件）+ Excel（财务/跟单二次加工）

**对称原则**：采购单与销售订单都是对外商务单据，**两套单据共用同一套导出范式**（openhtmltopdf + POI + DocProperties）。采购单 exporter 复制销售订单 exporter，仅做字段映射与采购特有增强。

## 二、销售订单已实现的范式（采购单对齐基准）

销售订单已落地完整的「详情导出 PDF/Excel 对外文档」功能，作为采购单的对齐基准：

### 2.1 技术栈（采购单零成本复用）

| 能力 | 实现 | 采购单复用 |
|---|---|---|
| **PDF 生成** | `openhtmltopdf`（openhtmltopdf-core + openhtmltopdf-pdfbox 1.0.10） | ✅ 依赖已就位 |
| **中文字体** | `fonts/NotoSansSC-Regular.ttf`（classpath 加载） | ✅ 字体已就位 |
| **抬头配置** | `DocProperties`（`qxx.doc`：companyName/Phone/Address/logoPath） | ✅ **直接复用，不硬编码、不动工厂表** |
| **Excel** | POI 手写 `XSSFWorkbook`（非 @Excel 注解，混排版式） | ✅ 依赖已就位 |
| **HTML 模板** | StringBuilder 拼字符串（无模板引擎） | ✅ 复制改字段 |

### 2.2 导出链路（采购单照搬结构）

```
Controller /exportPdf/{orderId} ──┐
                                   ├─> Service.getDetail(id)  ──> Exporter.write(detail, response.getOutputStream())
Controller /exportExcel/{orderId} ┘                            （复用已有详情聚合，无需改 Service）
```

- **Controller**：`SalOrderController.exportPdf/exportExcel`（`POST /mes/sal/order/exportPdf|exportExcel/{orderId}`，写 response 流，权限 `mes:sal:order:exportDetail`）
- **Exporter**：`SalOrderPdfExporter`（HTML→openhtmltopdf→PDF）、`SalOrderDetailExcelExporter`（POI 手写）
- **数据**：复用已有 `salOrderService.getDetail(orderId)`，**无需改 Service**
- **前端**：详情页 `detail.vue` + 列表页行内下拉，统一走全局 `proxy.download(url, {}, filename)`（blob 流）

### 2.3 版式区块（采购单复用骨架）

销售订单 PDF 五段式，采购单原样复用 + 采购增强：

1. **公司抬头**：Logo（base64 `<img>`）+ `{companyName} · 销售订单` + 联系行（电话·地址）+ 分割线
2. **信息网格**：键值对两列网格（订单号/日期/客户/业务员/付款方式/交期…）
3. **明细表**：带边框网格，序号/编码/名称/规格/数量/单位/单价/行金额
4. **合计 + 备注**：合计（小写+大写，取明细行之和）+ 工艺要求/备注
5. **签章栏**：业务员签字 / 客户盖章 / 日期

## 三、采购单对齐的 4 处差异（相对销售订单）

采购单复用整套范式，仅以下 4 处因采购业务特性需调整：

| # | 差异点 | 销售订单 | 采购单处理 |
|---|---|---|---|
| 1 | **对方主体信息** | clientName（订单上直接有，客户联系方式未展示） | vendorName（订单上有）+ **JOIN `qxx_md_vendor` 补供应商联系人/电话/地址**（采购单要明确供货方） |
| 2 | **币种** | 无 currency 字段 | **采购单有 `currency`**，信息网格 + 合计行都要显示币种 |
| 3 | **税额** | 无税率，金额单一 | **采购单明细有 `taxRate`**，金额拆「单价 / 行金额(不含税) / 税率」，合计拆「不含税合计 / 税额 / 价税合计」 |
| 4 | **收货地址** | 无（销售是发给客户，送货地址在出库单） | **采购是供应商发给采购方，必须显示收货地址/联系人/电话** —— 需补字段 |

### 3.1 字段映射表（SalOrder → PurOrder）

| 版式元素 | 销售订单字段 | 采购单字段 |
|---|---|---|
| 单号 | orderCode | orderCode ✅ |
| 日期 | orderDate | orderDate ✅ |
| 对方主体 | clientName | vendorName ✅ |
| 对方单号 | clientOrderCode（客户PO号） | sourceOrderCode（关联客户订单） |
| 经办人 | salesperson（业务员） | purchaser（采购员） |
| 审批 | （销售本次新加 approveBy） | approver（已有） |
| 交期 | requestDate | expectedDate ✅ |
| 付款 | paymentMethod | **payment_terms（需补字段）** |
| 币种 | （无） | **currency（已有，增强显示）** |
| 明细金额 | quantity/unitPrice/lineAmount | quantityOrdered/unitPrice/amount(不含税) + **taxRate（增强）** |

### 3.2 唯一的数据缺口：收货信息

采购单缺**收货地址 / 收货联系人 / 收货电话**（对外单据必备），需补字段。付款条件可复用现有表单录入或补字段。

```sql
-- V126__pur_order_delivery_fields.sql （参考 V121/V124 幂等写法）
ALTER TABLE qxx_pur_order
  ADD COLUMN delivery_address VARCHAR(255) DEFAULT NULL COMMENT '收货地址'   AFTER expected_date,
  ADD COLUMN delivery_contact VARCHAR(64)  DEFAULT NULL COMMENT '收货联系人' AFTER delivery_address,
  ADD COLUMN delivery_phone   VARCHAR(32)  DEFAULT NULL COMMENT '收货电话'   AFTER delivery_contact,
  ADD COLUMN payment_terms    VARCHAR(128) DEFAULT NULL COMMENT '付款条件'   AFTER total_amount;
```

> 注：抬头公司名**不需要**改工厂表（销售订单已用 `DocProperties` 配置解决，采购单直接复用 `qxx.doc`）。

## 四、采购单版式设计（PDF）

A4 竖版，五段式（对齐销售订单），采购增强币种/税额/收货信息：

```
┌───────────────────────────────────────────────────────────┐
│ [Logo]        {公司名} · 采购订单                            │  ← headerBlock（复用 DocProperties）
│              电话：xxx · 地址：xxx                           │
├───────────────────────────────────────────────────────────┤
│ 订单号: PURxxx    订单日期: 2026-08-13    状态: 已下单       │
│ 供应商: XX五金    供应商联系人: 李四  电话: 0755-xxx         │  ← infoGrid（JOIN MdVendor 补供应商信息）
│ 采购员: 张三      关联客户订单: SOxxx                        │
│ 币种: CNY         付款条件: 月结30天                        │  ← 采购增强：币种
│ 交货日期: 2026-08-20                                       │
│ 收货地址: 工厂A原料仓  收货人: 王五  电话: 139xxxx          │  ← 采购增强：收货信息
├──┬───────┬────────┬──────┬────┬──────┬────┬──────┬────┬─────┤
│序│物料编码│物料名称 │ 规格 │单位│ 数量 │单价│不含税│税率│税额 │  ← linesTable（采购增强：税率/税额）
│  │       │        │      │    │      │    │ 金额 │    │     │
├──┼───────┼────────┼──────┼────┼──────┼────┼──────┼────┼─────┤
│1 │M001   │螺丝M4  │...   │PCS │1000  │0.50│500.00│13% │65.00│
│2 │M002   │垫片    │...   │PCS │2000  │0.20│400.00│13% │52.00│
│                              不含税合计: ¥900.00            │
│                              税额: ¥117.00                  │  ← amountAndReq（采购增强：三段金额）
│                              价税合计: ¥1017.00（大写：壹仟零壹拾柒元整）
├───────────────────────────────────────────────────────────┤
│ 备注: 1.按期交货 2.质量标准见附件                            │  ← reqBlock
├───────────────────────────────────────────────────────────┤
│ 采购员（签字）:______  审批人:______  供应商确认（盖章）:____│  ← signBlock（采购：采购员/审批/供应商）
└───────────────────────────────────────────────────────────┘
```

**采购特有增强要点**：
- **明细金额三列**：单价 / 行金额(不含税) / 税率，比销售订单多「税率」列
- **合计三段**：不含税合计 / 税额 / 价税合计（含大写），比销售订单多税额拆分。税额 = `amount × taxRate/100`
- **收货信息行**：单独一行展示收货地址/联系人/电话（采购方指定地点）
- **供应商信息**：JOIN `qxx_md_vendor` 取 contact1/contact1Tel/address 补全（采购单只冗余了 code/name）
- **签章**：采购员 / 审批人 / 供应商确认（盖章），对称销售订单的「业务员/客户盖章/日期」

> 采购单 Excel 版（对内，仿销售订单 `SalOrderDetailExcelExporter`）：保留内部字段（已收量 receivedQuantity、取消量），无签章栏，便于财务对账。

## 六、关键实现参考（来自销售订单，采购单复制改字段）

### 6.1 PDF Exporter 核心（复制 SalOrderPdfExporter）

```java
@Component
public class PurOrderPdfExporter {
    @Autowired private DocProperties docProperties;  // 复用 qxx.doc
    static { XRLog.setLoggingEnabled(false); }

    public void write(PurOrder order, OutputStream out) throws Exception {
        PdfRendererBuilder builder = new PdfRendererBuilder();
        builder.useFastMode();
        builder.useFont(this::openFontStream, "NotoSansSC");   // 复用字体
        builder.withHtmlContent(buildHtml(order), null);
        builder.toStream(out);
        builder.run();
    }
    // buildHtml: headerBlock + infoGrid + linesTable + amountAndReq + signBlock
    //   infoGrid 增供应商(JOIN)/币种/收货信息
    //   linesTable 增税率列
    //   amountAndReq 拆不含税/税额/价税合计
    //   signBlock 改采购员/审批/供应商确认
}
```

### 6.2 Controller（复制 SalOrderController 导出两接口）

```java
@PreAuthorize("@ss.hasPermi('mes:pur:order:exportDetail')")
@Log(title = "采购订单明细PDF", businessType = BusinessType.EXPORT)
@PostMapping("/exportPdf/{orderId}")
public void exportPdf(@PathVariable Long orderId, HttpServletResponse response) throws IOException {
    PurOrderDetailVO detail = purOrderService.getDetail(orderId);
    FileUtils.setAttachmentResponseHeader(response, "采购订单_" + detail.getOrderCode() + ".pdf");
    response.setContentType("application/pdf");
    response.setCharacterEncoding("utf-8");
    pdfExporter.write(detail, response.getOutputStream());
}
// exportExcel 同构
```

### 6.3 前端导出调用（复制 sal）

```ts
function exportPdf() {
  proxy.download('mes/pur/order/exportPdf/' + orderId.value, {}, `pur_order_${order.value.orderCode}.pdf`)
}
function exportExcel() {
  proxy.download('mes/pur/order/exportExcel/' + orderId.value, {}, `pur_order_${order.value.orderCode}.xlsx`)
}
```
