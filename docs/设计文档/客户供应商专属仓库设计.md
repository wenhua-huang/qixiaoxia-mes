# 客户/供应商专属仓库 设计文档

> 状态：设计已确认，待实现　|　日期：2026-08-13　|　分支：feature/mes-wm-product-feedback

## 1. 背景与目标

### 1.1 用户需求
1. 仓库里的「客户仓库」不能给其他人发货（客户专属库存隔离，防错发）。
2. 出入库时，选择仓库时可以新增「库位」，库位可能是客户地址或供应商地址，需要名称+地址。
3. 给客户发货 = 按销售订单发货（走销售出库流程）。
4. 完成产品入库时记住客户，从而根据客户发货。
5. （补充）外协发料时优先从供应商仓库发料。

### 1.2 业务场景
按单生产（MTO）客户专属库存：成品产出时已确定归属某客户（定制件/订单生产），需专属存放，发货时严禁错发给别的客户。供应商侧对称：外协供应商的备料/寄存料优先从该供应商仓发料。

### 1.3 目标
- 产品入库按工单客户**定向入客户专属仓**，形成客户专属库存。
- 销售出库**硬隔离**：客户仓的货只能发给归属客户。
- 采购入库按供应商**定向入供应商专属仓**。
- 外协发料**软优先**：优先从供应商仓扣，不足补公共原料仓。
- 出入库选仓库时可**即时新建**带名称+地址+客户/供应商归属的仓。

## 2. 核心思路

**隔离边界 = 仓库。** 不改库存核心表 `qxx_wm_material_stock`（其唯一键已含 `warehouse_id`，不同客户/供应商 = 不同仓库 = 天然分桶）。

把用户口中的「库位（=客户/供应商地址）」落地为一种**带归属 + 地址的仓库**——**不引入独立的"库位"概念**：
- `warehouse_type = CUSTOMER`(客户仓) / `SUPPLIER`(供应商仓)
- `client_id` / `vendor_id` 标识归属
- 复用已有 `address` 字段（既是隔离边界，也是收发货地址）

> **「一个客户多个地址」如何处理**：库存物理隔离靠仓库——若货真的存放在多地（存放点），建多个客户仓即可；若是发货目的地不同（收货点），复用销售出库已有的 `shipping_address` 字段即可，**无需引入库位，本期也不另建地址簿**。

## 3. 现状与约束

| 维度 | 现状 | 影响 |
|------|------|------|
| 仓库层级 | 仓→库区→库位三级，但**库存实际聚合在仓库级**，库区/库位只是可选标注、不参与唯一键 | 隔离只能落到仓库级 |
| 仓库类型 | 仅 `RAW/FINISHED/AUX/LINE/TEMP`，无客户/供应商仓 | 需新增枚举 |
| 仓库表 | `qxx_wm_warehouse` **无** `client_id`/`vendor_id` | 需新增两字段 |
| 库存桶 | 唯一键=`物料+批次+仓库+供应商+工单+质量`，**无 client_id** | 不改：靠 warehouse_id 分桶 |
| 工单 `qxx_pro_workorder` | **已带** `sales_order_line_id` + `client_id`（销售订单转工单写入） | 入库可自动推导客户 |
| 产品入库 `qxx_wm_product_recpt` | **无** `client_id`，入库到「工厂第一个仓库」(`findDefaultWarehouse`) | 需加 client_id + 改入库目标仓逻辑 |
| 采购入库 `qxx_wm_item_recpt` | **已带** `vendorId/vendorCode/vendorName` | 供应商来源天然有，无需加字段 |
| 销售出库 `qxx_wm_product_sales` | 已有 `clientId` + 收货地址，扣库存按 warehouse 定位 | 加客户隔离校验即可 |
| 外协发料 | 草稿预填 FIFO（`batchFifoStocks`/`applyFifoStock`）**不按供应商过滤**，扣料按发料行 `warehouseId` | 改草稿选仓规则即可 |
| 前端选仓库组件 | `WarehouseSelect`/`LocationSelect` 只读，不支持即时新增 | 需改造 |

## 4. 方案选型

经评估三个方案，选定**方案①**：

| 方案 | 思路 | 改库存表 | 风险 | 选定 |
|------|------|:---:|------|:---:|
| ① 专属仓库 | 客户/供应商仓 = 带 `client_id`/`vendor_id` 的仓库，靠 `warehouse_id` 天然分桶 | 否 | 低 | ✅ |
| ② 库存桶加 client_id | `material_stock` 加 `client_id` 进唯一键 | 是（全库存 SQL） | 高 | ✗ |
| ③ 库位级隔离 | 库位加归属，库存桶 key 纳入库位 | 是（全定位 SQL） | 最高 | ✗ |

方案① 以最小改动达成隔离目标，且完全不碰系统最敏感的库存核心逻辑，回归面最小。

## 5. 数据模型设计

### 5.1 仓库表扩展 `qxx_wm_warehouse`
新增字段（均可空，默认 null = 普通仓）：
- `client_id` BIGINT NULL —— 客户仓归属客户（`warehouse_type=CUSTOMER` 时必填）
- `vendor_id` BIGINT NULL —— 供应商仓归属供应商（`warehouse_type=SUPPLIER` 时必填）

`warehouse_type` 枚举扩充注释（不改列定义）：
`RAW-原料仓, FINISHED-成品仓, AUX-辅料仓, LINE-线边库, TEMP-临时仓, CUSTOMER-客户仓, SUPPLIER-供应商仓`

约束（业务层校验，DB 不加强外键）：
- `CUSTOMER` → `client_id` 必填、`vendor_id` 必空
- `SUPPLIER` → `vendor_id` 必填、`client_id` 必空
- 其他类型 → 两者皆空

### 5.2 产品入库加客户 `qxx_wm_product_recpt`
头表新增字段：
- `client_id` BIGINT NULL —— 成品归属客户（来源=工单 `clientId`；备货工单为空）

### 5.3 采购入库 `qxx_wm_item_recpt`
**无需改表**——已自带 `vendorId/vendorCode/vendorName`。

### 5.4 库存隔离机制（不改 `qxx_wm_material_stock`）
- 客户仓/供应商仓的库存自动与公共仓分离（唯一键含 `warehouse_id`）。
- 成品库存桶 `vendor_id`/`workorder_id` 仍为 0（现状不变）。
- ⚠️ 概念区分：库存桶的 `vendor_id`（料属于哪个供应商）≠ 仓库的 `vendor_id`（仓归属哪个供应商），互不强绑定。

## 6. 业务流程

### 6.1 客户线闭环
```
销售订单 → 转工单(带 clientId) → 报工产出
   → 产品入库(带 clientId, 定向入客户仓)      ← 入库记客户
   → 客户专属库存(在客户仓)
   → 销售出库(从该客户仓发货, 校验客户一致)    ← 防错发(硬拦截)
```

### 6.2 供应商线闭环
```
采购订单 → 采购入库(带 vendorId, 定向入供应商仓)  ← 入库记供应商
   → 供应商专属库存(在供应商仓)
   → 外协发料(优先从该供应商仓发料, 不足补公共仓) ← 软优先
```

## 7. 关键规则

### 7.1 入库目标仓选择
**产品入库**（`ProWorkorderDocServiceImpl.generateReceiptDocuments` / `findDefaultWarehouse` 改造）：
- 工单有 `clientId` → 查该工厂下该客户的专属仓（`type=CUSTOMER + client_id + factory_id`）
  - 命中 → 入该客户仓
  - 未命中 → **提示引导**新建或选公共成品仓（不自动建仓，避免脏数据，决策 C）
- 工单无 `clientId`（备货生产）→ 入公共成品仓（现状不变）

**采购入库**（`WmItemRecptServiceImpl` 改造）：
- 有 `vendorId` → 默认/引导入该供应商专属仓（`type=SUPPLIER + vendor_id + factory_id`）
- 未命中 → 提示引导新建或选公共原料仓

### 7.2 销售出库硬隔离校验（决策 B）
在 `WmProductSalesServiceImpl` 扣库存前加校验：
```
if (出货仓库 warehouse_type == CUSTOMER) {
    要求 出库单.clientId == 仓库.clientId，否则拦截：
    "仓库[X]为客户[Y]专属仓，不能给客户[Z]发货"
}
// 公共成品仓(type != CUSTOMER)不受限，可发给任何客户
```
校验点：`postOut` / `postOutSingleBatch`，按实际扣库存的 warehouseId 校验。

### 7.3 外协发料软优先规则
改造 `OutsourceIssueHelper.batchFifoStocks` / `applyFifoStock`（草稿预填选仓）：
1. **优先**：该外协 `vendorId` 的供应商仓（`type=SUPPLIER + vendor_id`）里该物料可用库存 → 命中则填该仓+批次
2. **不足/无**：fallback 公共原料仓 FIFO（现状逻辑）
3. 扣料仍按发料行 `warehouseId`（`executeOutsource` 现状，0 改动）

注：外协发料是「软优先」（供应商仓不足允许补公共仓），与销售出库的「硬拦截」不同。

### 7.4 仓库选择器即时新增
`WarehouseSelect` 组件加「➕ 新增客户仓/供应商仓」入口 → 弹窗填：
- 仓库名称（必填）
- 地址（必填，=客户/供应商收发货地址，可从客户/供应商主数据带入）
- 归属客户 / 归属供应商（二选一，按类型）
- 建完即选入当前单据

本期覆盖入口（决策 D）：**产品入库、销售出库**（采购入库、领料等后续按需）。

## 11. 数据库迁移（Flyway）

新增迁移（版本号实现时取当前最大 +1，当前最大 V120，预计 **V121**）：
- `ALTER TABLE qxx_wm_warehouse ADD COLUMN client_id bigint(20) DEFAULT NULL COMMENT '客户仓归属客户ID(warehouse_type=CUSTOMER时必填)' AFTER warehouse_type;`
- `ALTER TABLE qxx_wm_warehouse ADD COLUMN vendor_id bigint(20) DEFAULT NULL COMMENT '供应商仓归属供应商ID(warehouse_type=SUPPLIER时必填)' AFTER client_id;`
- `ALTER TABLE qxx_wm_product_recpt ADD COLUMN client_id bigint(20) DEFAULT NULL COMMENT '成品归属客户ID(来源工单)' AFTER workorder_code;`
- 迁移内若需初始化字典/菜单 INSERT，显式写 `factory_id`（Flyway 裸 JDBC，不走拦截器）。
- 遵循项目幂等规范（`INFORMATION_SCHEMA` 判断列是否存在再 ALTER）。

## 13. 风险与验证

| 风险 | 应对 |
|------|------|
| 历史成品库存全在公共仓，新客户仓为空导致发货找不到货 | 客户仓为可选、增量启用；公共仓不受限 |
| 销售出库硬拦截误伤存量流程 | 仅当出货仓库明确为 CUSTOMER 仓才校验；公共仓不拦 |
| 外协发料优先逻辑改变现有 FIFO 行为 | 仅在供应商仓有库存时优先，无则完全等同现状 |
| 工单 clientId 为空（备货生产） | 入公共仓，与现状一致，不影响 |

验证清单：
1. 建客户仓 → 工单带客户 → 入库定向入客户仓 → 销售出库发货成功（同客户）
2. 从客户仓给其他客户发货 → 被拦截
3. 建供应商仓 → 采购入库入供应商仓 → 外协发料优先从供应商仓扣，不足补公共仓
4. 公共成品仓发货不受客户限制
5. 备货工单（无客户）入库仍入公共仓
6. 出入库时即时新建客户/供应商仓并选中
